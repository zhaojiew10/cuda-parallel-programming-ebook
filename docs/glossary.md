# CUDA 术语表

本表用于统一字幕中的中英文表达，帮助快速阅读；它不是完整的 API 参考。具体函数签名、设备限制和版本行为请以 NVIDIA 官方文档及实际环境为准。

## 编程与执行模型

| 术语 | 英文 | 本书中的含义 |
|---|---|---|
| 主机 | Host | 执行主机端代码的 CPU 及其系统环境。 |
| 设备 | Device | 执行 CUDA 核函数的 GPU；主机与设备也可以指代码或数据的所在侧。 |
| 核函数 / 内核 | Kernel | 由主机启动、在设备上由大量 CUDA 线程执行的函数。 |
| 网格 | Grid | 一次核函数启动所对应的线程块集合。 |
| 线程块 | Thread Block | 网格中的一组线程，可被调度到一个 SM 上，并能通过共享内存等方式协作。 |
| 线程索引 | `threadIdx` | 线程在其线程块内的三维索引。 |
| 线程块索引 | `blockIdx` | 线程块在网格内的三维索引。 |
| 线程块维度 | `blockDim` | 每个线程块在 x、y、z 方向上的线程数量。 |
| 网格维度 | `gridDim` | 网格在 x、y、z 方向上的线程块数量。 |
| 一维线性索引 | Global Thread Index | 将线程块索引、线程块维度和线程索引组合成全局索引；多维数据还需处理行宽等跨度。 |
| 流式多处理器 | Streaming Multiprocessor, SM | GPU 中调度线程束并管理相应执行资源的硬件单元。 |
| 线程束 | Warp | NVIDIA GPU 的 SIMT 执行线程组；课程按每组 32 个线程讨论。不是“波”“波段”或“波束”。 |
| 线程束通道 | Lane | 线程在线程束内的逻辑位置或索引。 |
| SIMT | Single Instruction, Multiple Threads | 单指令、多线程执行模型；同一线程束中的线程通常共同执行指令，但拥有各自的数据与状态。 |
| 线程束分化 | Warp Divergence | 同一线程束中的线程需要走不同控制流路径，导致不同路径分时执行的现象。 |
| 占用率 | Occupancy | 活跃线程束数量与硬件允许的最大活跃线程束数量之比；高占用率不必然等于高性能。 |
| 延迟隐藏 | Latency Hiding | 在某些线程束等待时调度其他可执行线程束，以利用计算资源。 |
| 动态并行 | Dynamic Parallelism | 设备端核函数启动其他核函数的 CUDA 能力。 |

## 内存与数据访问

| 术语 | 英文 | 本书中的含义 |
|---|---|---|
| 全局内存 | Global Memory | 可被设备上线程广泛访问的设备内存空间，容量较大但访问延迟较高。 |
| 共享内存 | Shared Memory | 位于 SM 上、由线程块内线程共享的低延迟内存；通常需要显式管理。 |
| 常量内存 | Constant Memory | 适用于只读、广播式访问的内存空间，具有特定缓存与访问特征。 |
| 局部内存 | Local Memory | 线程私有的逻辑内存空间；其物理位置和性能特征不等同于寄存器。 |
| 寄存器 | Register | 线程使用的高速片上存储资源，用量会影响每个 SM 可驻留的线程块或线程束数量。 |
| 页锁定内存 | Pinned / Page-locked Memory | 锁定在主机物理内存中的内存，常用于提高主机与设备间的传输效率，并支持异步复制。 |
| 零拷贝内存 | Zero-copy Memory | 设备通过主机内存映射直接访问数据，避免显式复制，但实际性能取决于访问方式。 |
| 统一内存 | Unified Memory | 提供主机和设备可共享访问的单一内存视图，不等同于消除所有数据迁移成本。 |
| 合并访问 | Coalesced Access | 同一线程束的内存访问以较少、较规则的事务完成，通常要求连续、对齐等合适模式。 |
| AoS | Array of Structures | 结构体数组：每个元素的多个字段连续存放。 |
| SoA | Structure of Arrays | 数组结构体：不同字段分别存放在独立数组中。 |
| 存储体 | Shared Memory Bank | 共享内存的并行访问组织单位；课程按 32 个存储体讨论。 |
| 存储体冲突 | Bank Conflict | 同一线程束中的访问因映射到不合适的存储体与地址组合而产生额外串行化。 |
| 填充 | Padding | 在数据中增加额外间隔，以改变地址映射并缓解特定存储体冲突。 |
| 矩阵转置 | Matrix Transpose | 交换矩阵行列位置的操作，常用于研究全局和共享内存访问模式。 |

## 同步、流与性能

| 术语 | 英文 | 本书中的含义 |
|---|---|---|
| 同步 | Synchronization | 确保执行先后关系或数据可见性的操作，不同 API 的作用范围不同。 |
| 块内同步 | `__syncthreads()` | 同一线程块内线程的同步点，不是整个网格的全局同步。 |
| CUDA 流 | CUDA Stream | 一组按提交顺序执行的 CUDA 操作；不同流可用于表达并发。 |
| 默认流 / 空流 | Default / NULL Stream | 未显式指定流时使用的流，其同步语义受创建方式和运行环境影响。 |
| CUDA 事件 | CUDA Event | 流中的标记，可用于等待、建立依赖或在合适配置下进行 GPU 时间测量。 |
| 异步函数 | Asynchronous Function | 调用后主机可在设备操作完成前继续执行；是否真正异步还取决于参数、内存和流语义。 |
| 重叠执行 | Overlap | 将数据传输与核函数执行，或不同设备操作，在合适硬件与程序条件下并发安排。 |
| 性能分析 | Profiling | 通过工具收集时间、指令、内存和硬件指标，以定位瓶颈。 |
| nvprof | NVIDIA Profiler | 课程使用的旧版命令行分析工具；新环境应检查 Nsight 系列工具的适用性。 |
| 归约 | Reduction | 将一组值通过结合运算得到一个或若干结果，例如求和、最大值。 |
| 循环展开 | Loop Unrolling | 减少循环控制开销并增加指令级并行机会的技术，也可能增加寄存器压力。 |
| 线程束展开 | Warp Unrolling | 当归约范围缩小到线程束尺度后，利用线程束执行与通信特征减少部分同步或控制开销。 |
| 线程束洗牌 | Warp Shuffle | 在线程束内不同通道之间直接交换寄存器数据的指令机制。 |
| 原子函数 | Atomic Function | 对同一地址执行不可分割读—改—写等操作，用于避免特定竞态，但竞争会影响性能。 |
| 内建函数 | Intrinsic Function | 映射到特定硬件指令或实现的函数，速度、精度和适用范围可能与标准函数不同。 |

## 并行模式与图像处理

| 术语 | 英文 | 本书中的含义 |
|---|---|---|
| 前缀和 / 扫描 | Prefix Sum / Scan | 按给定二元运算计算各位置之前或包含当前位置的累积结果。 |
| 包含扫描 | Inclusive Scan | 输出位置包含当前输入元素的扫描。 |
| 排他扫描 | Exclusive Scan | 输出位置不包含当前输入元素，只累积其之前元素的扫描。 |
| 工作高效 | Work-efficient | 算法总工作量与高效串行算法保持相近量级；并行步数少并不必然代表总工作量低。 |
| 压缩 / 筛选 | Stream Compaction | 保留满足条件的元素并紧凑输出，通常可结合谓词、扫描和散射实现。 |
| 数字图像处理 | Digital Image Processing | 使用计算方法表示、变换、增强或分析数字图像。 |
| OpenCV | Open Source Computer Vision Library | 常用的计算机视觉与图像处理库；CUDA 支持取决于具体模块和构建配置。 |
